# AstraScan

**A C++20 network inventory scanner with TLS inspection, structured reports, inventory diffs, and CI exposure policies.**

AstraScan is an original, Nmap-inspired project for repeatable TCP inventories on systems you are authorized to assess. Its focus is a compact scanner and a straightforward reporting workflow: scan → save JSON → compare inventories → enforce policy.

This is an early **0.1.0** release, not a replacement for Nmap's mature discovery engine. It does not implement raw SYN scans, UDP scans, OS fingerprinting, NSE, vulnerability exploitation, stealth, or firewall evasion. No Nmap source or signature database is included.

## Features

- **IPv4 and IPv6 TCP connect scans** without root privileges.
- **Hostnames, IPv4 CIDR, target files, exclusions, deduplication**, and a scope preview with `--dry-run`.
- **Bounded concurrency**, global connection-start rate limiting, per-phase timeouts, and configurable retries.
- **Passive service banners** and recognition of SSH, HTTP, and VNC response prefixes. Other service names are explicitly marked as port hints in JSON.
- **HTTP HEAD** on common HTTP ports and optional **HTTPS** inspection.
- **TLS protocol, cipher, certificate subject, issuer, and expiration** via OpenSSL 3. Certificate trust is not verified and is explicitly reported as such.
- **Text, JSON, CSV, and self-contained HTML** reports; HTML escapes remote evidence, and CSV neutralizes formula prefixes.
- **Atomic report file replacement** with private file permissions.
- **Ctrl+C / SIGTERM partial reports**, deterministic result ordering, and stable exit codes.
- **Inventory diff tool** that separates scope changes from state changes, ignores timing noise, and detects certificate metadata changes.
- **Exposure policy tool** for allowed ports, required TLS handshakes, and certificate expiration thresholds; usable as a CI gate.
- **No third-party C++ dependencies beyond optional OpenSSL**. Python helpers use the standard library.

## Quick start

Supported and tested platform: Linux with GCC 14, C++20, OpenSSL 3, and Python 3.9+. CI also exercises Clang and a build without TLS. CMake 3.20+ is optional when using Make. Windows is not supported; macOS portability has not been validated.

```bash
# Debian / Ubuntu build dependencies
sudo apt-get update
sudo apt-get install -y build-essential libssl-dev python3 openssl

git clone https://github.com/Ayonokoji111/astrascan.git
cd astrascan
make -j2
./build/astrascan --version

# Preview the scope before making connections
./build/astrascan 127.0.0.1 -p 22,80,443 --dry-run

# Scan a machine you control
./build/astrascan 127.0.0.1 -p 22,80,443 --services --tls --http
```

Run `make test` for loopback-only tests. `make TLS=0 BUILD=build-no-tls` creates a separate build without OpenSSL; `--tls` is rejected by that build. Do not reuse a build directory when changing build flags.

Optional CMake build:

```bash
cmake -S . -B build-cmake -DCMAKE_BUILD_TYPE=Release
cmake --build build-cmake -j2
ctest --test-dir build-cmake --output-on-failure
```

## Inventory workflow

```bash
mkdir -p reports

# All hosts in this CIDR, excluding one address. Use your authorized scope.
./build/astrascan 192.168.1.0/28 --exclude 192.168.1.1 \
  -p 22,80,443,8080,8443 --rate 100 --workers 32 \
  --services --tls --http --format json -o reports/before.json

# Repeat later with the same scope/options
./build/astrascan 192.168.1.0/28 --exclude 192.168.1.1 \
  -p 22,80,443,8080,8443 --rate 100 --workers 32 \
  --services --tls --http --format json -o reports/after.json

python3 tools/astra-diff.py reports/before.json reports/after.json --fail-on-change
python3 tools/astra-diff.py reports/before.json reports/after.json --format json

# Edit policy.example.json to match your actual authorized environment first
python3 tools/astra-policy.py reports/after.json docs/policy.example.json

# An HTML report is generated by another scan, not a conversion of saved JSON
./build/astrascan 127.0.0.1 -p 22,80,443 --format html -o reports/scan.html
```

Diff and policy tools require **complete JSON reports without `--open`**. Filtered/error endpoints fail policy evaluation as inconclusive. A policy result applies only to endpoints actually scanned: an unscanned port is not evidence of a closed port. See [policy semantics](docs/USAGE.md#policies-and-ci).

## How this relates to Nmap

| Capability | AstraScan 0.1 | Nmap |
| --- | --- | --- |
| Unprivileged TCP connect scan | Yes | Yes |
| IPv4 / IPv6 targets | Yes | Yes |
| IPv4 CIDR / target files / exclusions | Yes | Yes |
| Service identification | Small port map + 3 banner prefixes | Extensive signatures and probes |
| TLS certificate metadata | Built in on selected ports | Available through scripts |
| Raw SYN, UDP, OS detection, scripting engine | Not implemented | Available |
| JSON and standalone HTML output | Built in | Other formats; conversions available |
| JSON inventory diff and exposure policy gate | Bundled Python helpers | External tooling / Ndiff / scripts |

AstraScan's extra workflow conveniences do not establish greater scan accuracy, speed, or protocol coverage than Nmap. No comparative performance claims have been measured.
